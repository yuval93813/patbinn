# Data

This directory holds the two scripts that build the dataset and the manifests
that record exactly what was built. **The manifests are checked in; the genomes
and reads they point at are not**. They are large and fully regenerable from
NCBI plus these files.

```
download_genomes.py    NCBI multi-isolate downloader; assigns CV folds
simulate_reads.py      ART Illumina read simulator; propagates folds
manifests/             The scientific record (checked in)

refs/                  Downloaded genome FASTAs        (generated, gitignored)
reads_multi/           Simulated reads                 (generated, gitignored)
vocab*/                Cached k-mer vocabularies       (generated, gitignored)
manifests_*/           Per-run fold manifests          (generated, gitignored)
kraken2_db_*/          Kraken2 reference database      (generated, gitignored)
```

To regenerate everything, follow steps 1-2 of the Quickstart in the
[root README](../README.md).

## Manifests

### Class definitions

These list *which classes exist*, before any genome is downloaded.

| File | Rows | What it is |
|---|---|---|
| `generalization_manifest.csv` | 58 | **The class list this project uses.** The 58 classes with enough real isolate diversity on NCBI to support a held-out-genome benchmark. |
| `full_manifest.csv` | 64 | The original 64-class list, before 6 classes were dropped for insufficient isolates. Kept for provenance, see [docs/EXPERIMENTS.md](../docs/EXPERIMENTS.md#class-selection-58-kept-6-dropped). |
| `pilot_manifest.csv` | 4 | A 4-class subset for smoke-testing the pipeline end to end without a multi-hour download. |

Columns: `family, family_idx, variant, variant_idx, organism, title_keyword`.
`organism` is the field-tagged NCBI `[Organism]` query term; `title_keyword` is
the word-boundary-matched validation keyword.

### Genome records

These record *which actual genomes were retrieved*, one row per isolate.

| File | Rows | What it is |
|---|---|---|
| `genome_manifest_multi.csv` | 543 | **The genome record for every result in this repository.** 58 classes × 3-10 independent isolates, each with its CV fold. |
| `genome_manifest.csv` | 64 | The original one-genome-per-class record from the superseded single-genome experiment. |

Key columns beyond the class definition: `accession` (NCBI UID), `length`,
`defline` (whose first token is the citable accession.version), `fasta_path`,
`isolate_idx`, and `fold`.

**`fold` is assigned here**, at isolate granularity, as `isolate_idx % K`. This
is the mechanism that prevents genome-level leakage; see
[docs/PIPELINE.md](../docs/PIPELINE.md).

A human-readable rendering of this file, with every accession grouped by family
and variant, is [docs/GENOME_INVENTORY.txt](../docs/GENOME_INVENTORY.txt),
regenerated by `python3 scripts/make_genome_inventory.py`.

### Sample records

These record *which simulated read sets exist*, one row per replicate.

| File | Rows | What it is |
|---|---|---|
| `cv_sample_manifest.csv` | 3,258 | **The main sample manifest.** 543 isolates × 6 ART replicates. Input to `src/run_cv.py`. |
| `final_train_manifest.csv` | 3,258 | The same samples with a `split` column for the no-holdout final model (`src/train_final_model.py`). |
| `cv_fold0_sample_manifest.csv` | 2,484 | Fold 0's materialized train/val/test split. |
| `cv_fold1_sample_manifest.csv` | 2,982 | Fold 1's materialized split: the one every single-fold sweep and the Kraken2 comparison use. |
| `sample_manifest.csv` | 384 | Sample manifest from the superseded single-genome experiment. |

Columns: `sample_id, family, family_idx, variant, variant_idx, isolate_idx,
replicate, r1_path, r2_path, fold` (plus `split` where the split has been
materialized).

The per-fold manifests are produced by `src/run_cv.py` and are checked in so that
any single-fold experiment can be reproduced without re-running the whole CV
orchestrator.

## Invariants worth preserving

1. **Every row sharing an `isolate_idx` within a `(family, variant)` shares the
   same `fold`.** `simulate_reads.py` asserts this at write time. It is the
   guarantee that no genome's reads are split across train and test.
2. **`remap_variant_idx()` must be called on the complete row set before any
   fold-filtering.** Remapping a pre-filtered subset yields indices that do not
   match what the checkpoint was trained with.
3. **The k-mer vocabulary is built per fold, from that fold's training rows
   only.** A vocabulary built over all rows would leak which k-mers are common
   in held-out isolates.
